# MobiChecklist v0.1.0 설계

## 목적과 범위

Windows에서 마비노기 모바일을 창 모드로 플레이할 때 사용하는 수동 체크리스트. 항상 위에 표시하지만 게임 데이터 접근, 입력 자동화, 이동 자동화를 하지 않는다. Python 3.10 이상과 PySide6를 사용한다.

이 문서는 구현 기준이다. 기본 앱 구현을 시작했으며 실제 Windows 검증은 별도 단계다. 기존 구현의 UI와 저장 형식을 전제로 하지 않는다.

## 핵심: 상세 보기와 간략 보기

헤더의 보기 전환 버튼 하나로 전체 창을 전환한다. 개별 카드의 체크 항목을 숨기는 접기 기능은 제공하지 않는다.

### 간략 보기 (접힘)

방문 번호, 지역명, 체크 항목을 표시한다. 이동 안내, 심층 설정, 설명 문구, 주간 기록 버튼, 별도 진행률 영역은 숨긴다. 헤더에는 펼치기 버튼만 남기고 제목·투명도·닫기 버튼은 숨긴다. 카드 사이에는 아래 방향 순서 화살표를 표시한다. 조회 날짜와 오늘 복귀는 상세 보기에서 제공한다.

```text
┌────────────────────────────────┐
│ MobiChecklist · 수 10/14   ≡ ◐ ×│
├────────────────────────────────┤
│ 1  콜헨                  ← 다음│
│    ☐ 레이드                    │
│    ☐ 촉매                      │
├────────────────────────────────┤
│ 2  이멘마하                    │
│    ☐ 룬다                      │
│    ☐ 심층 매우 어려움 · 공물 2 │
├────────────────────────────────┤
│ 3  이벤트 · 위치 확인          │
│    ☐ 이벤트 확인               │
└────────────────────────────────┘
```

위 예시는 수요일에 심층 위치를 이멘마하로 설정한 경우다. 카드는 항상 세로 한 열로 배치한다. 번호는 체크 여부와 무관하게 유지하고 완료 카드를 자동으로 숨기거나 재정렬하지 않는다. 첫 미완료 카드는 색 테두리와 `다음` 표식으로 강조하며 색에만 의존하지 않는다.

### 상세 보기 (펼침)

동일한 카드와 체크 항목에 날짜·완료 수치, 카드 목록 위의 금주의 매우 어려움 심층던전 위치 설정, 카드 사이 이동 안내, 주간 기록 진입 버튼을 추가한다. 상세 보기에서도 카드 순서와 번호는 동일하다. 이동 안내는 번호 없는 텍스트이며 체크 대상이 아니다.

```text
┌────────────────────────────────┐
│ MobiChecklist             ≡ ◐ ×│
│ 2026-10-14 수요일 · 0/5 완료    │
│ 이번 주 심층: [이멘마하     ▾] │
│ 레이드 퀵메뉴 → 대기방 → 나가기│
├────────────────────────────────┤
│ 1  콜헨                  ← 다음│
│    ☐ 레이드                    │
│    ☐ 촉매                      │
├────────────────────────────────┤
│ 2  이멘마하                    │
│    ☐ 룬다                      │
│    ☐ 심층 매우 어려움 · 공물 2 │
├────────────────────────────────┤
│ 이벤트 위치는 직접 확인하세요 │
│ 3  이벤트 · 위치 확인          │
│    ☐ 이벤트 확인               │
├────────────────────────────────┤
│ [주간 기록]                    │
└────────────────────────────────┘
```

보기 전환은 표시 방식만 변경한다. 체크, 선택 날짜, 심층 위치, 카드 번호를 변경하거나 저장 기록을 초기화하지 않는다. 심층 미설정 경고는 간략 보기에서도 지역 제목에 남긴다. 과거 날짜에는 상세 보기에서 `과거 기록` 표식과 오늘 복귀 버튼을 제공한다.

## 창과 스크롤 규칙

- 기본 폭은 약 360 논리 픽셀. 실제 글꼴과 Windows DPI에 맞게 최소 폭을 보정한다.
- 높이는 현재 보이는 내용의 실제 레이아웃 높이와 헤더·여백으로 계산한다. 숨긴 상세 요소의 높이를 포함하지 않는다.
- 화면 작업 영역 높이를 상한으로 사용한다. 상한 이하에서는 내용에 맞게 줄이고, 넘을 때만 카드 영역에 세로 스크롤을 표시한다.
- 헤더와 상세 보기의 설정·하단 버튼은 스크롤 영역 밖에 둔다. 카드와 이동 안내는 스크롤 영역 안에 둔다.
- 전환 후 레이아웃 계산이 끝난 시점에 높이를 한 번 갱신한다. 이전 위젯 크기, 고정 카드 높이, 이전 스크롤 높이를 재사용하지 않는다.
- 카드 상태 변경은 기존 위젯을 갱신한다. 전체 카드 목록을 매 체크마다 재생성하지 않는다.
- 화면 이동이나 DPI 변경 시 작업 영역과 높이를 다시 계산하고 창이 화면 밖으로 벗어나지 않게 위치를 보정한다.
- 보기 전환 시 현재 화면 맨 위 카드의 식별자를 기준으로 스크롤 위치를 유지한다. 전체 내용이 화면에 들어오면 스크롤은 처음으로 돌아간다.
- 헤더의 빈 영역을 드래그해 이동한다. 버튼 클릭과 드래그 동작은 구분한다. 항상 위 표시, 투명도 조절, 닫기 기능을 제공한다.

## 숙제와 동선

| 요일 | 고정 기본 동선 |
|---|---|
| 월 | 이멘마하 룬다 → 던바튼 주간 정산 → 티르코네일 골드 |
| 화 | 던바튼 보석 → 이멘마하 룬다 |
| 수 | 레이드 TP 안내 → 콜헨 레이드·촉매 → 이멘마하 룬다 |
| 목 | 이멘마하 룬다 → 티르코네일 골드 |
| 금 | 던바튼 보석 → 이멘마하 룬다 |
| 토 | 레이드 TP 안내 → 콜헨 레이드·촉매 → 어비스 TP 안내 및 3회 → 이멘마하 룬다·주말 보상 |
| 일 | 이멘마하 룬다 → 선택 던전 → 주말 미완료 확인 |

매일 심층 매우 어려움(공물 2개)과 이벤트 확인을 추가한다. 레이드 TP는 대기방 입장 후 나가기로 콜헨 이동 가능하다는 안내이고, 어비스 TP는 실제 클리어가 필요하다는 안내다. TP 안내는 완료 수치에 포함하지 않는다.

심층 위치는 월요일을 기준으로 주간별 저장한다. 이미 방문하는 지역이면 해당 카드에 통합한다. 위치 미설정이면 기본 동선 뒤에 경고 카드를 배치한다. 이벤트와 선택 던전은 위치를 아는 것처럼 경유 계산에 넣지 않는다.

기본 동선을 바꾸지 않고 심층만 경유지로 추가한다. 실제 지도상의 지역 순서와 선택 가능한 심층 위치 목록이 아직 확인되지 않았으므로 임의 순서를 코드에 넣지 않는다. 확인 전에는 선택한 심층 지역을 기본 동선 뒤 별도 카드로 보여 주고 상세 보기에서 `경유 순서 미확정`을 표시한다. 최단 경로나 비용 최적화로 표현하지 않는다.

토요일 어비스는 `− 0/3 +` 형태의 카운터이며 두 보기에서 모두 조절 가능하다. 주간 완료 수치는 어비스를 3개 완료 단위로 계산한다. 따라서 카운터 1이면 완료 수치도 1 증가한다.

## 기록과 날짜

- `%LOCALAPPDATA%\MabiChecklist\state.json` 경로를 사용한다.
- 로컬 날짜에서 6시간을 뺀 날짜를 게임 날짜로 사용한다. 한국 게임 날짜에 맞추려면 PC 시간대를 한국으로 설정한다.
- 날짜가 바뀌면 오늘 화면만 새 날짜로 전환한다. 과거 기록을 열어 둔 경우 선택 날짜는 유지한다.
- 주간 기록은 월~일의 완료/전체 수치를 표시하고 이전·다음 주 탐색, 날짜 선택 및 수정이 가능하다. 주간 기록창은 상세 보기에서 연다.
- 표시 이름과 무관한 고정 숙제 ID로 기록한다. 지역 이동이나 문구 수정으로 체크가 사라지지 않는다.
- 설정(보기 모드·투명도·창 위치)과 날짜별 완료 기록, 주간 심층 위치를 분리한다.
- 임시 파일 작성 후 원자적 교체로 저장하며 직전 파일을 백업한다. 저장 실패는 화면에 알리고 저장 성공처럼 표시하지 않는다.
- 기존 저장 형식이 없으므로 과거 버전 호환을 보장하지 않는다. 알 수 없는 형식·깨진 JSON은 덮어쓰지 않는다. 지원할 마이그레이션은 실제 샘플과 별도 테스트가 있을 때 추가한다. 이전 테스트 구현의 schema 1 및 같은 구조의 버전 없는 기록은 변환하며, 지원하는 JSON 파일 불러오기와 원본 백업 후 새 시작을 제공한다.
- 닫기 버튼과 시스템 종료 동작은 날짜 감시 타이머를 멈추고 Qt 이벤트 루프를 종료한다.

## 구현 구조

| 구성 | 역할 |
|---|---|
| 일정 모델 | 요일별 숙제, 고정 ID, 완료 단위 |
| 동선 모델 | 카드 그룹화, 확정된 심층 경유 규칙, 이동 안내 |
| 기록 저장소 | 버전 있는 JSON 읽기·쓰기, 백업, 오류 보호 |
| 날짜 서비스 | 06:00 경계, 주간 기준, 날짜 변경 알림 |
| 메인 창 | 동일 카드 위젯에 상세/간략 표시 정책 적용 |
| 주간 기록창 | 주간 집계, 날짜 탐색 및 선택 |
| 투명도 팝업 | 슬라이더, 설정 저장 |

## 구현 및 검증 순서

1. 가짜 일정 데이터로 두 보기의 UI를 먼저 구현한다. 두 모드에서 체크 항목은 항상 표시되어야 한다.
2. 7일치 카드, 어비스 카운터와 첫 미완료 강조를 연결한다.
3. 저장·복구·06:00 경계와 주간 기록을 연결한다.
4. 실제 지역 자료를 확인한 뒤 심층 경유 규칙을 추가한다.
5. Windows에서 오버레이와 DPI·다중 모니터 동작을 검증하고 EXE를 빌드한다.

필수 UI 검증: 7일 각각 보기 전환 20회, 모든 카드 완료/일부 완료/미완료, 긴 텍스트, 100%·125%·150% DPI, 작은 화면, 다중 모니터 이동. 카드 누락·번호 변동·빈 공간 누적이 없어야 하고 모든 체크 항목에 스크롤로 접근할 수 있어야 한다.

필수 로직 검증: 05:59→06:00, 월요일 주간 경계, 과거 기록 수정, 어비스 0~3 제한, 심층 지역 통합, 미설정 경고, 저장 실패·깨진 파일 보호. 실제 게임 창 위 표시와 종료 후 프로세스 종료는 Windows에서 확인한다.

## 투명도 팝업

상세 보기의 투명도 버튼 바로 위에 슬라이더만 있는 작은 팝업을 표시한다. 화면 위 공간이 부족하면 버튼 아래에 표시한다. 바깥 클릭으로 닫히며 조절 값은 자동 저장한다.

위 텍스트 시안의 헤더는 초기 구상이며 간략 보기의 최종 버튼 구성은 펼치기 하나다.
